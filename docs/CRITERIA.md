# Соответствие критериям кейса

Числа из `reports/judge_check.json` (проверочный bag организаторов, алгоритм сопоставления их скрипта), `reports/replay_dayout_bursts.json` и `reports/replay_dayout.json` (ориентиры, тупики и свои участки карты без дня проверяемой записи; GNSS пачками как в проверочном bag или только первые 32 с), `reports/ablation.json`, `reports/benchmark.json` и `reports/ros_check.json`. Эталон положения на обучающих записях: `base_link` в плоских MGRS и высота, по обеим антеннам и tf, как следует из ответов экспертов.

Проверочный bag организаторов `30618_88aea4d9`: скорость RMSE 0,0245 м/с, положение RMSE 3D 0,98 м (x 0,79, y 0,57, z 0,04 м), медиана 0,45 м.

## 1. Точность скорости (0..30)

| Что оценивается | Что сделано | Результат |
|---|---|---|
| СКО и средняя абсолютная ошибка | колёса в км/ч переведены в м/с; фильтр Калмана по модели привода; масштаб колёс уточняется по ориентирам; скорость публикуется с запаздыванием эталона судьи 0,1 с | проверочный bag 0,0245 м/с; медиана по обучающим записям 0,034 м/с; все пары 0,113 (0,039 без сбоев эталона); MAE 0,028 |
| Переходные режимы | модель даёт ускорение, выход экстраполируется на метку по ускорению; колёса и GNSS совмещены по времени с точностью 20 мс | СКО на разгонах и торможениях в отчёте (`v_rmse_transient`) |
| Отсутствие смещения | средний масштаб не навязан, он оценивается в каждом рейсе | среднее смещение −0,002 м/с |
| Остановки | на месте при нулевой или тормозной позиции модель держит 0 | `v_rmse_stop` в отчёте |

## 3. Устойчивость и проскальзывание (0..20)

| Требование | Реализация | Проверка |
|---|---|---|
| Снижать доверие к недостоверной одометрии | темп колеса против физики (боксование, юз), согласие тележек, строб невязки, гистерезис, выбор тележки по режиму | отказ датчика: 0,051 против 0,584 м/с у среднего тележек; юз 0,031 против 0,089; боксование 0,033 против 0,081 |
| Без всплесков и расходимости | на модели скорость ограничена физикой, СКО растёт честно; пересинхронизация через 4 с | графики `docs/img/slip_cases.png` |
| Пропуски и выбросы | опоздавшие сообщения приводятся к текущему моменту; при молчании колёс выход продолжается по модели; NaN, бесконечности, неверные типы и позиции вне диапазона отбрасываются | тесты `tests/test_odometria.py` |
| Не падать и восстанавливаться | ядро не бросает исключений на входных данных; новая запись со скачком времени перезапускает оценку | тест `test_reset_on_new_recording` |
| Флаг и диагностика | `/result/slip_detected`, `/result/diagnostics`: состояние каждой тележки, коэффициент проскальзывания, использованное сцепление, поправка модели, масштаб колёс, СКО, привязки к ориентирам | `node.py: _diagnostics` |
| Адаптивная подстройка | поправка модели `b` в фильтре, масштаб колёс `k` в облаке частиц | масштаб за рейс определяется с точностью около 0,1 % |

## 4. Реальное время и производительность (0..15)

| Требование | Решение | Замер |
|---|---|---|
| Задержка ≤ 100 мс | публикация прямо в обработчике входа, без очередей; ядро p99 0,25 мс, максимум 9,7 мс | в ROS 2 через DDS p50 4,0 мс, p99 9,1 мс, максимум 48 мс (`latency_probe`) |
| Частота ≥ 10 Гц, желательно 20..50 | сетка 50 Гц, при молчании колёс выход идёт от контроллера | 48 Гц в ROS 2, 47 Гц в среднем по всем записям офлайн |
| ≤ 2 ядер, ≤ 0,5 ГБ | один поток; облако частиц трогается только на остановках | процесс узла 65 МБ, 13 % одного ядра (42 % при проигрывании ×4); ядро 0,14 % ядра и 3,4 МБ (`reports/benchmark.json`, `reports/ros_check.json`) |
| Без утечек и гонок | однопоточный исполнитель, буферы ограничены | прогон записи 31,6 мин |
| colcon build без интернета | ament_python и ament_cmake, зависимости только из ROS Humble, узел без numpy; исправлен package.xml сообщений организаторов (не хватало maintainer) | сборка в образе `ros:humble`, `tools/ros_check.sh`; вместе с проверочным узлом организаторов `tools/judge_ros.sh` |
