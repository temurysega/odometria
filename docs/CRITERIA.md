# Проверка по критериям кейса

Это технический самоаудит, а не прогноз баллов жюри. Офлайн анализатор использует время записи SQLite; судья сверяет опубликованные ROS сообщения по `header.stamp`.

| Критерий PDF | Что сделано | Что ещё ограничивает результат |
|---|---|---|
| Скорость, 0–30 | Нелинейная модель привода, адаптивная поправка, фильтрация двух тележек. На 87 записях с GNSS: 1 677 162 пары, совокупный RMSE 0,131 м/с, медиана по записи 0,036 м/с. | Максимум отдельной записи 0,670 м/с. Нужно проверить совпадение временных меток и отказы в настоящем ROS воспроизведении. |
| Положение, 0–35 | Интеграция скорости, две статические карты пути, GNSS только при начальной привязке. На 85 записях, не использованных для карт: 851 520 пар, RMSE 2D 20,23 м и 3D 21,99 м против 4,33 км у прежнего `x=путь`. | Требуется подтвердить систему координат судьи, допустимость карты из обучающего GNSS и работу на маршрутах вне двух карт. Две записи из 85 не попали на карту. |
| Устойчивость, 0–20 | Проверки пропусков, устаревшего контроллера, расхождения тележек и модельной невязки. При недостоверных колёсах применяется прогноз; длинный разрыв сохраняет путь с повышенной неопределённостью. Публикуются `/result/diagnostics` и `/result/slip_detected`. | Общая пробуксовка обоих колёс наблюдается только через модельную невязку; полностью отделить её от ошибки модели по трём входам нельзя. Нужна серия прогонов с искусственными отказами и отчёт о ложных тревогах. |
| Реальное время, 0–15 | По длинному bag суммарная частота событий колёс около 19,3 Гц. На Windows чистый шаг наблюдателя: p99 0,0102 мс на 50 000 вызовах. | ROS 2 Humble и `colcon build` в этой Windows среде недоступны. Задержка «вход → публикация», устойчивость частоты и память полного узла не измерены. |

## Следующие проверки с наибольшим влиянием

1. На Ubuntu 22.04 с ROS 2 Humble выполнить `colcon build --symlink-install`, запустить узел и воспроизвести один длинный bag. Измерить частоту обоих обязательных топиков и задержку по времени получения сообщения и публикации.
2. Сравнить `Odometry.pose.pose.position.{x,y,z}` с локальной системой координат судьи. Сейчас ENU начало — первый валидный GNSS фикс, карта строится по обучающим записям. Точная конвенция эталона в PDF не задана.
3. Провести отложенную проверку карты на других маршрутах и добавить их статические полилинии только из разрешённых обучающих данных. Не использовать будущие GNSS сообщения проверочного прогона.
4. Проверить модель на контролируемых сценариях общей пробуксовки, юза, замерзания одного датчика и длительного пропуска. Зафиксировать RMSE, дрейф, задержку обнаружения и долю ложных тревог.

Команды для воспроизведения результатов без ROS:

```bash
python tools/analyze_dataset.py /path/to/dataset/data --output reports/bag_analysis.json
python tools/evaluate_position.py --data /path/to/dataset/data --output reports/position_analysis.json
python tools/benchmark_observer.py
python -m unittest discover -s tests -v
```
