# Разбор предоставленного датасета

Исходные данные: архив `dataset.zip` из условий кейса (вложенный `data.zip`, README датасета, пакет `tram_vehicle_msgs`). Сырые bag в репозиторий не входят. Все цифры ниже получены инструментами из `tools/` и воспроизводимы.

## Состав

| | |
|---|---|
| Каталогов rosbag2 SQLite | 122 (103 вагона 30618, 19 вагона 30639) |
| Побайтные дубли | 25 пар (одинаковые время записи, заголовки и значения всех топиков), уникальных записей 97 |
| Суммарно уникальных данных | 28,7 ч, 8,8 млн сообщений во всех каталогах |
| Записи с GNSS | 78 уникальных; 19 без единого сообщения GNSS (в основном утро 10 августа) |
| Дни записи | 5 мая (30639), 27 июля, 10 августа, 26 августа (оба вагона), 3 сентября |
| Рейсы | 35 на запад и 32 на восток от кольца до кольца, остальные короткие или неполные |

Дубли исключаются при любой оценке (`tools/bagdata.py: unique_bags`), иначе они завышают вес части поездок.

## Сигналы

| Топик | Частота | Особенности |
|---|---|---|
| `/vehicle/front_bogie_velocity`, `/vehicle/rear_bogie_velocity` | 10 Гц каждая, вместе около 20 Гц | значение в **км/ч**, коэффициент 1/3,6 подтверждён по GNSS на всех записях; заголовок на 30..70 мс раньше времени записи |
| `/vehicle/driver_position_cmd` | 20 Гц, два издателя | целое −15..15, меняется шагами ±1; заголовок почти равен времени записи, то есть на 50 мс позже шкалы колёс |
| `/sensing/gnss/*/fix`, `/sensing/gnss/*/vel` | 10 Гц | заголовки строго на сетке 0,1 с; скорость в `twist.linear` по ENU |

В первые 0,3..0,5 с каждой записи приходит пачка буферизованных сообщений с заголовками на 1..3 с старше времени записи. Узел это переносит: шкала времени строится по заголовкам, опоздавшие измерения приводятся к текущему моменту через ускорение.

## Колёса против GNSS

Поиск задержки по минимуму СКО дал 0 с с шагом 20 мс на всех проверенных записях и для master, и для rover. На чистых участках среднее двух тележек совпадает со скоростью GNSS с СКО 0,025 м/с, это уровень шума самого GNSS.

Масштаб (путь GNSS к пути колёс) по записям:

| Группа | Масштаб |
|---|---|
| 30618, 27 июля, 10 и 26 августа | 1,000..1,0017 |
| 30618, 3 сентября | 1,007..1,016 |
| 30639, 5 мая | 0,985..0,995, плавный рост за день |
| 30639, 26 августа | 1,003..1,004 |

Отношение слабо зависит от скорости (на 1..3 м/с на 0,2..0,3 % выше, чем на 10+ м/с): на малых скоростях трамвай идёт по кривым, где антенна на крыше описывает чуть больший радиус. Постоянный масштаб на все рейсы дал бы до 80 м ошибки к концу; поэтому масштаб оценивается онлайн по ориентирам.

## Геометрия

Все поездки идут по одной двухпутной линии: восточное разворотное кольцо, 5,4 км почти прямых участков, западная конечная с несколькими тупиками и кольцом. Пути встречных направлений разнесены на 4 м. Rover стоит на 12,40 м впереди master у обоих вагонов (медиана по всем записям 12,40..12,44 м), по линии антенн определяется курс.

RTK фиксы разных поездок ложатся на общую осевую с медианным отклонением 1 см. Карта строится так: опорная поездка на каждое направление параметризуется колёсным путём, выбросы режутся скользящей медианой, затем осевая уточняется медианой поперечных отклонений и высот всех поездок; основной ход (по 4,7 км в каждую сторону) заменяется картами организаторов; направления сшиваются у восточной платформы, западное кольцо добавляется по поездке, которая его прошла с RTK. Итог: замкнутый контур 11 051 м, шаг 1 м, в плоских MGRS.

## Карты организаторов

Две линии («таллинская – щукинская» и обратно) по 4709 точек с шагом 1 м, поля x, y, z, курс и кривизна. Координаты совпадают с UTM зоны 37 минус 300 000 / 6 100 000 м (квадрат MGRS, x продолжается за 100 км). Поперёк пути они отличаются от RTK траектории master на 3 см (медиана), высота на 3,10 м ниже антенн, то есть карты описывают `base_link` (tf антенн z = 3,0 м).

Сравнение с RTK выявило участок около 400 м западного хода, где 27 июля все рейсы шли по соседнему пути в 4 м (объезд), а 5 мая, 10 и 26 августа и 3 сентября по пути из карты организаторов. Медиана по всем поездкам выбирала путь 27 июля (в этот день больше всего RTK), поэтому основной ход теперь берётся из карт организаторов.

Высота RTK содержит всплески до 5 м под путепроводами; для уклона профиль сглаживается медианой по 31 м, а дуговая координата считается в плане, иначе всплеск удлиняет путь на метры.

## Остановки

845 остановок дольше 2 с сгруппированы вдоль контура в 48 мест. У платформ медианное отклонение 0,1..0,4 м, редкие выбросы (встал не у платформы, очередь) на 5..25 м. Вагон 30639 останавливается на 0,13 м иначе, чем 30618, то есть ориентиры общие. Для каждого места сохраняется доля рейсов, которые там останавливались: она становится весом ориентира в правдоподобии.

|---|---|---|

| Юз обеих | 30618_68d1748a, 994 с | задняя до 4,8, передняя до 5,7 при реальных 7,3 |
| Боксование обеих | 30618_33bec73f, 103..111 с | колёса до 5,2 и 7,3 м/с при реальных 3,8..4,3, темп +3..4 м/с² |
| Отказ датчика | 30639_3b3d9eb8, 376..495 с | задняя залипает в ноль на ходу, потом 2 мин без сообщений |
| Залипание на старте | 30639_d927f360, 1060 с | задняя 0 при начале движения, контроллер 0 |
| Экстренное торможение | 30618_616ec56b, 1020 с | обе тележки и GNSS тормозят до −5 м/с² при контроллере 0 |

Последний случай важен: физически это не проскальзывание, а рельсовый тормоз, которого нет в сигнале контроллера. Решение, которое отбраковывает колёса по несогласию с моделью, здесь ошибается на 3..4 м/с, поэтому плотное согласие двух тележек имеет приоритет над моделью.

| Тип | Пример | Влияние |
|---|---|---|
| Скорость GNSS ноль на ходу | 30618_4d487b0d, 100..132 с | ошибка до 7 м/с у любого решения |
| Скачок метки GNSS на ±1 с | 30618_40ffd323, 85..147 и 440..520 с | эталон сдвинут на секунду: ±1 м/с на разгонах, до 10 м по положению |

Метрики в отчётах считаются дважды: по всем парам (как у судьи) и без первых двух типов сбоев, чтобы видеть собственную ошибку решения.

## Время и сопоставление

Судья сопоставляет выход с эталоном по ближайшей метке с допуском 0,05 с. Эпохи GNSS лежат на сетке 0,1 с, поэтому узел публикует на сетке 20 мс в шкале заголовков колёс: каждой эпохе эталона соответствует выход ровно в её момент, а между эпохами сохраняется частота 50 Гц. Значение на узел сетки экстраполируется по модели от последнего измерения (не дальше 10 мс вперёд). Оценка приводится для обоих вариантов сопоставления (выход к эталону и эталон к выходу), расхождение между ними меньше 1 %.
