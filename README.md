# Резервная одометрия трамвая

ROS 2 Humble пакет, который по положению контроллера и скоростям передней и задней тележек оценивает продольную скорость и пройденное расстояние. Вход GNSS в рабочем узле отсутствует. GNSS читается отдельным офлайн анализатором для оценки ошибки на предоставленных записях.

## Состав

- `src/tram_vehicle_msgs` — типы сообщений из предоставленного датасета.
- `src/odometria` — ROS 2 узел и независимая от ROS модель наблюдателя.
- `tools/analyze_dataset.py` — чтение rosbag2 SQLite и сравнение скорости с GNSS без ROS.
- `reports/bag_analysis.json` — результаты прогона анализатора по датасету.

## Сборка и запуск

В Ubuntu 22.04 с установленным ROS 2 Humble:

```bash
source /opt/ros/humble/setup.bash
cd odometria
colcon build --symlink-install
source install/setup.bash
ros2 run odometria odometry_node
```

Во втором терминале:

```bash
source /opt/ros/humble/setup.bash
cd odometria
source install/setup.bash
ros2 bag play /path/to/dataset/data/30618_01f73500
```

Узел подписывается на `/vehicle/front_bogie_velocity`, `/vehicle/rear_bogie_velocity`, `/vehicle/driver_position_cmd` и публикует `/result/velocity` типа `tram_vehicle_msgs/msg/VelocitySensor` и `/result/position` типа `nav_msgs/msg/Odometry`. В `Odometry` продольная координата записана в `pose.pose.position.x`; `y` и `z` равны нулю. Это относительная координата вдоль пути в метрах. Параметр `initial_distance` задаёт стартовое значение.

Параметры ROS: `traction` (м/с² при полной тяге), `braking` (м/с² при полном торможении), `wheel_agreement` (допустимое расхождение тележек, м/с), `wheel_speed_scale` (перевод сырого значения в м/с; по умолчанию `1/3.6`), `initial_distance` (м). Например:

```bash
ros2 run odometria odometry_node --ros-args -p wheel_speed_scale:=0.2777777777777778
```

Для локальной проверки без ROS:

```bash
python tools/analyze_dataset.py /path/to/dataset/data --bag 30618_01f73500
python -m unittest discover -s tests -v
```

## Модель и ограничения

Контроллер `u = position / 15` проходит через апериодический привод. Модель ускорения:

`a = A max(u,0)/(1+v/v0) + B min(u,0) - R tanh(v/0.3) - D v² + b`.

Здесь `b` — ограниченная адаптивная поправка к сопротивлению или уклону. Скорость прогнозируется моделью, затем корректируется согласованными показаниями тележек. При расхождении тележек или большой невязке с прогнозом измерение отклоняется. Положение интегрируется по оценённой скорости; неопределённость растёт при отсутствии достоверных колёс. Параметры модели пока начальные и требуют дополнительной проверки на сложных проскальзываниях.

Из трёх разрешённых скалярных входов невозможно восстановить направление движения и абсолютные координаты `x/y/z` без карты пути или начальной внешней привязки. Текущий узел публикует только относительное расстояние вдоль пути и помечает поперечные координаты большой ковариацией. Это ограничивает сопоставление с трёхмерной GNSS траекторией по требованию README датасета.

В реальных bag значения `VelocitySensor.velocity` численно соответствуют км/ч, несмотря на указанные в README датасета м/с. Коэффициент `1/3.6` подтверждён сравнением с GNSS на записях обоих трамваев. Заголовки разных входных топиков также имеют взаимные смещения; узел синхронизирует входы по времени получения. Для сообщения передней тележки публикуется его исходный `header.stamp`, для задней — экстраполяция по последнему заголовку передней тележки. Точность временного совмещения выходов следует проверять в ROS 2 Humble на целевом стенде.
